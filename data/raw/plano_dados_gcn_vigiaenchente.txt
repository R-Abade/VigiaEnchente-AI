1. DIAGNÓSTICO: LACUNAS NO MODELO ATUAL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PROBLEMA 1 — Data Leakage no label y
  Situação atual: y = exp(-river_dist / threshold) ≈ x[river_dist_norm]
  Efeito: o modelo aprende uma função de identidade, não estrutura do grafo
  Solução: y deve incorporar elevação + precipitação acumulada + evento real

PROBLEMA 2 — Features insuficientes em x
  Situação atual: x = [degrees_norm, betweenness_norm]
  Ausente: elevação topográfica (decisiva — um nó a 40m do rio em altitude
           alta tem risco menor que um nó a 80m do rio em várzea)
  Ausente: contexto temporal (precipitação acumulada)
  Ausente: tipo de via (ponte/túnel da OSM)

PROBLEMA 3 — Sem supervisão real
  O modelo não tem nenhuma amostra rotulada por evento histórico real.
  Todos os 1659 nós têm labels sintéticos derivados de distância euclidiana.

PROBLEMA 4 — GCN estrutural favorece nós centrais
  Nós ribeirinhos periféricos (os mais críticos) recebem scores menores
  porque têm poucos vizinhos. Isso justifica migração para GAT.

ETAPA 3 — Construir nova label y por nó
  y_node(i, t) = risk_score composto:

  COMPONENTE ESTÁTICO (independe do tempo):
    base_risk = 0.5 * exp(-river_dist[i] / threshold)   # proximidade ao rio
              + 0.5 * (1 - elevation_norm[i])            # baixa elevação = risco maior
              → range: [0, 1]

  COMPONENTE DINÂMICO (varia por snapshot temporal t):
    temporal_amplifier = sigmoid(
        2.0 * (precip_72h[t] / 100)  # normalizado pelo limiar PLANCON
    )  → range: [0.5, 1.0]

  LABEL FINAL:
    y_base = base_risk * temporal_amplifier

  SUPERVISÃO REAL (quando disponível):
    if flood_label[t] > 0:
        y_supervised = flood_label[t] * (river_dist_norm[i] ** 0.5)
        y_final = max(y_base, y_supervised)   # conservativo: pega o maior
    else:
        y_final = y_base

  RESULTADO: y é fisicamente significativo, não derivável trivialmente de x

TENSOR x (nova dimensão: 7 features por nó)
────────────────────────────────────────────
  Índice  Feature              Tipo        Fonte         Justificativa
  ──────  ───────              ────        ─────         ─────────────
  0       degree_norm          Estático    OSMnx         Conectividade (já existe)
  1       betweenness_norm     Estático    NetworkX      Centralidade (já existe)
  2       river_dist_norm      Estático    OSMnx+Shapely Proximidade ao rio (já existe)
  3       elevation_norm       Estático    SRTM          CRÍTICO: diferencia várzea de encosta
  4       precip_72h_norm      Temporal    Chuvas.csv    Principal driver de cheias (NOVO)
  5       is_wet_season        Temporal    Calendário    Sazonalidade risco (NOVO)
  6       is_bridge            Estático    OSM           Pontes bloqueiam primeiro (NOVO)

  Racional para o TCC: "A feature de elevação resolve o problema de data leakage
  porque introduz informação ortogonal à distância euclidiana ao rio. A feature
  de precipitação acumulada 72h permite ao modelo aprender que o mesmo nó tem
  diferentes níveis de risco em dias secos versus eventos extremos — algo que
  o GCN estático não consegue capturar."

LABEL y (nova formulação)
──────────────────────────
  ATUAL:  y = exp(-river_dist / threshold)  [idêntico à feature x[2]]
  NOVO:   y = f(river_dist, elevation, precip_72h, flood_event)
  
  Formula explícita:
    base  = 0.5 * exp(-river_dist / 50)        # decaimento exponencial ao rio
           + 0.5 * (1 - elevation_norm)         # baixa altitude = risco maior
    amp   = sigmoid(2 * precip_72h / 100)       # amplificador temporal
    y_raw = base * amp                          # [0, 1]
    
    # Supervisão com eventos reais (8 datas confirmadas)
    if evento_historico:
        y_super = flood_severity * exp(-river_dist / 100)
        y = max(y_raw, y_super)
    else:
        y = y_raw

Sobre a escolha dos dados:
  "Os dados utilizados provêm da ANA (Agência Nacional de Águas) via portal
  HidroWeb, que é a fonte oficial de monitoramento fluviométrico e
  pluviométrico no Brasil. A estação 1943006 (Sabará) possui série contínua
  desde 1941, com 84 anos de dados que permitem caracterizar a climatologia
  local e identificar anomalias nos eventos de enchente."

Sobre a validação cruzada:
  "Os dados pluviométricos confirmam todos os 5 eventos registrados no Plano
  Municipal de Gerenciamento de Riscos e Desastres (PLANCON 2025). O evento
  de janeiro/2020 registrou 606mm no mês — o maior da série 2000-2025 — com
  pico de 266mm em 72 horas, 2,6 vezes o limiar de alerta de 100mm definido
  pelo próprio PLANCON para acionamento do sistema de contingência."

Sobre a label y:
  "A label anterior sofria de data leakage: a distância ao rio era tanto
  feature de entrada quanto variável alvo, fazendo o GCN aprender uma função
  trivial de identidade. A nova formulação incorpora elevação topográfica
  (SRTM/NASA) e precipitação acumulada 72h, tornando o label fisicamente
  interpretável e quebrando a dependência linear com as features de entrada."

Sobre os 8 eventos supervisionados:
  "Com apenas 8 datas confirmadas de eventos reais, o modelo opera em um
  regime semi-supervisionado: a maioria das amostras usa o label físico
  derivado, enquanto as 8 datas de eventos históricos fornecem ancoragem
  supervisionada direta. Esse design é consistente com a literatura de GNNs
  aplicados a desastres naturais, onde ground truth rotulado é escasso."
